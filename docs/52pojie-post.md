## 正文

【起因】

工作机上的微信常年最小化，来消息只有任务栏闪一下。想看一眼是谁找，就得把微信整个拉起来，看完再最小化——一天几十次，纯属折磨。

也试过几个现成方案，都不太合适：有的要装客户端全家桶，有的直接读微信本地数据库（SQLCipher 加密，还得跟着版本改），还有的要注入进程，杀软第一个不答应。

后来发现 Windows 自己就有现成的通道：微信收到消息会往通知中心推 Toast。那就别费劲去啃微信了，直接读系统通知就行。于是有了这个小工具。

【效果】

缩在后台时，屏幕角落浮出一张卡片，告诉你哪个会话、谁发的、说了什么，3 秒自动淡出。鼠标移上去会暂停倒计时，点一下直接把微信唤到前台。

【功能一览】

· 悬浮卡片：圆角 + 柔和阴影，两行正文，超长省略
· 真实头像：把图片按「会话名.png」丢进头像目录就能显示，没匹配上的用渐变首字兜底
· 自动消失：默认 3 秒，悬停暂停，移开继续
· 多条堆叠：同屏最多几张可调，多出来的排队
· 点击跳转：点卡片唤起微信主窗口
· 可视化调参：宽度、缩放、圆角、阴影、透明度、间距、位置、时长全可调
· 深浅两套主题
· 配置永久保存：改完自动落盘，不用点保存，重启不丢
· 托盘常驻：可暂停监听，单实例保护

【怎么实现的】

这部分是重点，也是踩坑最多的地方。

一、先试的正路，走不通

最直觉的做法是 UI Automation：遍历微信窗口的控件树，把会话列表和消息文本读出来。这个思路在微信 3.x 时代是常见做法，但 4.x 彻底变了。

微信 4.x 把界面换成了 Qt 自绘（窗口类名 `Qt51514QWindowIcon`，内部是 `MMUIRenderSubWindow`）。自绘意味着整块区域对 UIA 来说就是一个空白画布——实测主窗口的控件树只有 3 个节点，没有任何会话或消息。这条路直接判死。

二、换个思路：读通知中心

微信收到新消息时，会按系统规范往 Windows 推送 Toast 通知。用 `UserNotificationListener` 就能把这些通知读出来，不需要任何特殊权限之外的骚操作。

读出来的文本结构非常规整，固定三行：

　　text[0]　应用名　　微信
　　text[1]　会话名　　产品研发群
　　text[2]　发送者+正文　　张伟 : 这个版本的接口文档我下午更新一下

`text[2]` 是「发送者 + 正文」拼在一起的，得切开来。

这里不能简单地按第一个冒号切——正文本身完全可能带冒号（比如「时间：明天下午三点」），一刀下去就把正文切坏了。实际用的是一条带约束的正则：从行首开始匹配，发送者最长 24 个字符，后面紧跟中英文冒号都算。

　　　　^(.{1,24}?)\s*[:：]\s*(.+)$

限定长度是为了兜底：真人昵称很少超过 24 个字，超过的基本就是正文里的冒号，不匹配就整段当正文，至少不会切错。群聊和单聊都走这一套。

三、几个必须处理的细节

· 首次启动要建基线。通知中心里存着历史通知，不做处理的话程序一启动就会把几十条旧消息全弹一遍。做法是首次运行时把现有通知的「ID → 文本签名」全部记下来，只记录不弹窗。
· 判断「新」不能只看 ID。同一条通知可能因为内容更新（比如连发两条被合并）而文本变化，所以比对的是 ID 对应的文本签名，签名变了才算新消息。
· 去重。用「会话 + 发送者 + 正文」做 key，4 秒窗口内重复的直接丢弃。
· 用轮询而不是事件。`UserNotificationListener` 其实提供了 `NotificationChanged` 事件，但在 PyWinRT 里维持回调对象的生命周期比较别扭，回调还落在别的线程上，得自己再往 UI 线程转一道。相比之下 1 秒一次的 `get_notifications_async` 简单、稳、开销可以忽略，就选了轮询。

四、UI 部分

PySide6 画的。卡片是 QPainter 自绘：先叠几层递减透明度的圆角矩形做阴影，再画主体。背景单独设透明度，文字保持不透明——不然整张卡片一起半透明，字会糊。

堆叠用 QPropertyAnimation 做位移和淡入淡出，新卡片插进来时其余卡片平滑下移。

【安全性说明】

这类工具大家最关心的应该是这个，我一次说清楚：

· 不联网。程序没有任何网络请求，不收集、不上传任何数据。
· 不注入进程。没有 DLL 注入，没有 Hook，不碰微信的内存。
· 不读数据库。微信的 `head_image.db` 是 SQLCipher 加密的，程序压根没去动它。
· 只读系统通知。走的是 Windows 官方 `UserNotificationListener` API，和系统通知中心看到的是同一份数据。
· 源码全公开，MIT 协议，不放心的可以自己审、自己编。

关于杀软误报：PyInstaller 单文件打包出来的 exe 有一定概率被某些杀软标记，这是打包方式的通病，不是程序行为异常。介意的话直接用源码跑，依赖就几个包，`pip install -r requirements.txt` 然后 `python main.py` 就行。

【使用方法】

1. 下载 `WeChatToast.exe`，双击运行。托盘出现绿色「微」图标就是启动成功了，没有主窗口是正常的。
2. 右键托盘图标 → 设置…，按自己喜好调参数。改完直接关窗口，自动保存。
3. 想暂停就点托盘菜单的「暂停监听」。

两个前提开关必须打开，否则读不到任何东西：

· 微信 → 设置 → 通知 → 开启「新消息通知」
· Windows → 设置 → 隐私和安全性 → 通知 → 允许应用访问你的通知

配置文件在 `%APPDATA%\WeChatToast\config.json`，想手动改的可以直接编辑。exe 挪位置、重新下载覆盖，配置都不会丢。

【已知限制】

提前说清楚，免得下载完发现不符合预期：

· 只读通知，拿不到历史消息，也不能在卡片里直接回复。
· 点击只能把微信唤到主窗口，没法定位到具体某个会话——4.x 是自绘的，外部点不进去。
· 图片、表情、语音消息在通知里没有正文，卡片会显示「（新消息）」。
· 微信本身会合并同一会话的连续消息，这时候可能只弹一次。
· 你正开着微信、且正看着那个会话时，微信不发通知，所以不会弹卡片。这是符合预期的。
· 微信如果关了系统通知，本工具收不到任何东西。

【环境】

· Windows 10 1809+ / Windows 11
· 微信 PC 版 4.x（实测 4.1.15.13；3.9.x 走的也是系统通知，理论上可用但未实测）
· 源码运行需要 Python 3.10+
